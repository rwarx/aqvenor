# Идеи для Canvas

Дата: 9 ноября 2026 года. Область: Electron Canvas Aqvenor.

**Только идеи — не реализовано.** По просьбе пользователя этот документ не сопровождается изменениями Canvas, API или тестов. Оценки сложности относительные, без обещания сроков.

При подготовке прочитаны текущие компоненты и контракты. Уже доступны поиск и фильтрация, minimap, pan/zoom, фокус выделения, авторазмещение, выравнивание и распределение, множественное выделение, undo/redo, заметки, подписи и переподключение связей, Ask AI, перенос файлов в composer и чата на карту. Ниже предлагаются дополнения к этим возможностям.

| Идея | Сценарий и польза | Сложность | Основные зависимости |
| --- | --- | --- | --- |
| **1. Сохранённые представления** | Сохранить «Главная страница», «Оплата» или «Проверки» вместе с камерой, фильтром и набором узлов. Одним действием возвращаться к части проекта после работы в редакторе или чате. | Низкая–средняя | Workspace-bound хранение представлений, устойчивые ID узлов, обработка исчезнувших узлов после reindex. |
| **2. Сворачиваемые области** | Объединить файлы, план и заметки в область «Лендинг кофейни»; сворачивать её в одну карточку. При сворачивании показывать число файлов и внешние связи, при разворачивании возвращать расположение. | Средняя–высокая | Серверный контракт областей и portable schema, проекция внешних связей, undo для группировки. Содержимое графа остаётся целым. |
| **3. Исследование связей от узла** | Выбрать форму заказа и показать только входящие/исходящие связи на 1–3 шага или путь до выбранного сервиса. Помогает понять окружение без ручного поиска каждого соседа. | Средняя | Ограниченный обход графа, фильтр видов связей и направления, лимиты на большие графы, возврат к прежнему представлению. |
| **4. Предпросмотр изменений ИИ на карте** | Агент предлагает архитектуру страницы; новые узлы и связи появляются в отдельном слое, удаляемые элементы отмечаются. Пользователь видит пространственный результат до применения, может принять согласованный набор или отклонить его. | Высокая | Контракт предложения, base hash/snapshot, связь с run и approval, перепроверка после изменения графа, единая серверная операция применения. |
| **5. Изменения и проверки на карте** | После работы агента показать изменённые файлы и относящиеся к ним результаты сборки/тестов. Из карточки переходить к настоящему diff или логу, быстро находить место ошибки. | Средняя–высокая | Сопоставление workspace-relative путей с узлами, Git/checkpoints, структурированные результаты команд и run ID. |
| **6. Сохранённые наборы контекста для агента** | Собрать «Hero + форма + стили», выбрать глубину соседей, исключить нерелевантные узлы и увидеть итоговый контекст перед отправкой. Повторять задачи по одной части проекта без нового ручного выделения. | Средняя | Расширение существующего GraphContextSource и composer, явный список включённых файлов/заметок, лимиты контекста, повторная проверка текущего workspace. |
| **7. Карточки результата с web-превью** | Прикрепить к узлу лендинга актуальный скриншот, ссылку на локальное превью и дату проверки. Сопоставлять устройство проекта с результатом, открывать страницу и проверку из одной карточки. | Средняя–высокая | Реальные артефакты run, безопасное открытие разрешённого локального preview URL, управление сроком жизни preview-процесса, хранение screenshot как артефакта. |

## Что отличает идеи от существующих функций

1. Сейчас сохраняется текущая камера; идея добавляет **несколько именованных представлений**, а не ещё одну кнопку фокуса.
2. Группировка в Graph Outline относится к списку видов узлов. Идея добавляет **пользовательские области непосредственно на карте**.
3. Текстовый поиск уже есть. Новое представление строится по **топологии и направлению связей**. Индексатор сейчас создаёт связи `Contains`; это не доказательство вызовов или импортов. Для содержательного анализа зависимостей нужны существующие ручные/агентские связи либо отдельная будущая семантическая индексация.
4. Инструменты агента уже добавляют узлы и связи через общий graph service. Идея добавляет **пространственный просмотр до применения**, сохраняя действующие approvals. Она не заменяет проверку файлового diff.
5. Diff, checkpoints, статусы узлов и траектория запуска уже существуют. Новое — **их доказуемая привязка к карте**. Статус `done` от модели не должен превращаться в надпись «тесты прошли»; результат требует настоящего лога, команды, exit code и времени. Отсутствие проверки показывается явно.
6. Ask AI, pin файлов и GraphContextSource уже дают контекст. Новое — **именованный состав с управлением включением и предварительным просмотром**, а не второй механизм чтения графа.
7. Открытие файла уже есть; карточка результата даёт **визуальный артефакт продукта**. Старая картинка должна отмечаться как устаревшая, если относящиеся к ней файлы изменились.

## Порядок для будущего обсуждения

Начать с **сохранённых представлений** и **исследования связей**: они дают ежедневную пользу и могут сначала работать как проекции существующего графа. Затем рассмотреть наборы контекста и слой изменений/проверок. Области, предпросмотр предложений ИИ и карточки web-результатов требуют отдельных контрактов и проверки на реальных проектах.

Для любой будущей реализации сервер остаётся единственным владельцем графа; все мутации проходят через общий coordinator. Новое persistent-состояние требует совместимого формата, а не прямой записи renderer в `canvas.json`. Представления и артефакты привязаны к workspace; запоздавший ответ старого проекта не может попасть в новый. Сравнение предложений использует содержимое/base hash, поскольку `GraphSnapshot.Version` может уменьшаться при undo.
