## Aqvenor v0.3.1-alpha

**Still an alpha.** This is a small corrective release: the model you pick stays picked, the chat
tells you it is working before the first token, and three pieces of chrome leave the window.

### What to do

- **If you were on `0.3.0-alpha`: take this one.** Your database, settings, conversations and
  DPAPI-encrypted keys are unchanged. There is no migration.
- **If you have not installed it yet:** the [full description is here](https://github.com/rwarx/aqvenor#readme),
  and the one that matters is in *What you need* below.

### What you need

- Windows 10 version 1809 or later, or Windows 11
- The [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download) - the sidecar process the
  app starts is framework-dependent
- An API key from a provider configured in Settings - the app installs and runs without one; it
  simply cannot talk to a model

### The chosen model stays chosen

Each chat keeps its own agent, but the pick only lived in the renderer. After a run the transcript
was reloaded from the conversation row, which still carried the model the chat was *created* with,
so a custom-provider model (or anything other than the default Claude Sonnet 4.5) appeared to snap
back on every request.

- The picker now writes `providerId`/`modelId` to the conversation as well as to the store.
- A transcript pull keeps the chat's own model and only falls back to the server's stamp when the
  session has no model of its own. Custom-provider ids (`custom-.../model`) survive the round trip.
- The status bar reads the open chat's model, not the global default for new chats, so it can no
  longer disagree with the composer's model pill.

### Sending is never silent

A run can spend seconds - minutes on a reasoning model - before the provider emits its first
token. The transcript used to stay blank for that whole gap.

- A thinking row appears as soon as the run starts: the live phase label, the three-dot pulse and
  the shimmer line, in the same visual language as a streaming answer.
- It disappears when the assistant bubble arrives, and the transcript scrolls to follow it.
- A failed request still lands as an inline error on the reply, never as an empty bubble.

### Less chrome

- **`IDLE` is gone** from the status bar. The corner reports work only while there is work.
- **`LIVE AI` is gone** from assistant messages. The answer is already attributed to its model by
  the header line; the badge repeated it on every turn.
- **The sidebar's import/export button is gone.** Session bundles remain available from the
  context panel and the project header.
