## Aqvenor v0.3.2-alpha

Released on 8 November 2026.

**Still an alpha.** This release makes graph persistence recoverable and adds
updates from GitHub Releases. It also includes the editor, workspace and
connection fixes made since `0.3.1-alpha`.

### Installation and updates

- Windows 10 version 1809 or later, or Windows 11, on x64.
- The installer now includes the sidecar's .NET runtime; a separate .NET SDK or
  runtime installation is unnecessary.
- Install this version from the attached installer if you use `0.3.1-alpha` or
  earlier. Those versions do not contain an updater. Starting with this release,
  the Windows Electron app checks GitHub Releases and downloads newer builds.
- Restart to install a downloaded update from Settings. Installation goes
  through the normal save/close flow; an unsuccessful save keeps the window open.
- Your profile, conversations and encrypted provider keys stay in the same
  locations. An API key is needed only when you want to use a model.

### A graph with one source of truth

- The server owns the saved graph. The renderer and the project's
  `.aqvenor/canvas.json` follow that graph instead of writing competing versions.
- An existing portable canvas is imported when a project has no saved graph.
  Later writes update the portable format atomically, including the viewport.
- Graph and portable-save failures are visible and retryable. Pending edits stay
  in memory, and switching projects cannot apply an old project's changes to a
  new one.
- A canvas changed externally is protected from silent overwrite. Private
  viewport persistence continues to work when the project folder is read-only.
- Recovery saves preserve unreadable private graph and viewport files in
  verified `.corrupt-*.json` copies beside the originals before replacing them.

### Updates from GitHub Releases

- Checks run after startup and during long sessions. Settings shows the current
  version, update state and download progress, with a manual check and retry.
- Alpha builds accept newer alpha, beta or stable releases. Stable builds accept
  stable releases. Draft releases and older versions are excluded.
- Downloads use the published installer metadata and SHA512 verification. Every
  release also includes SHA256 checksums and its exact source commit.
- Installation starts only after your restart action and successful completion
  of the save/close flow. Development builds do not check for updates.
- Checks and downloads contact GitHub; they send no project files, chats or
  provider keys. See [the update documentation](https://github.com/rwarx/aqvenor/blob/v0.3.2-alpha/docs/AUTO-UPDATES.md)
  and [privacy policy](https://github.com/rwarx/aqvenor/blob/v0.3.2-alpha/PRIVACY.md).

### Reliability fixes since 0.3.1

- **Workspace recipes:** use the open project and the intended Code or Cowork
  mode, with explanations when a busy chat, draft, attachment or another project
  prevents launch.
- **Large files and diffs:** bounded diff calculation avoids the previous
  quadratic allocation. Applying selected changes preserves complete file
  contents, and editor/checkpoint operations keep large files and line endings.
- **Backend connection:** every surface reports a lost connection. Retry can
  recover an unsuccessful startup without reloading unsaved editor buffers or
  chat drafts. It checks connectivity; it does not restart a terminated sidecar.
- Project leases and stale-hash checks protect file writes, agent runs and
  checkpoints during project changes. Concurrent saves and runs are serialized.
- Starting a chat no longer loses its draft, approvals or attachments when the
  server assigns the conversation ID. A disconnect cancels the active run and
  its approval wait.
- Electron IPC validates its renderer and main frame. Imported project MCP
  servers begin disabled and require desktop approval. The sidecar validates
  listener addresses before startup.

### Limits

The application can write files and run programs through an agent, so review
approvals and keep normal project backups. There is no telemetry or project-run
cloud service. Windows installers currently have no Authenticode signature;
GitHub publication access and HTTPS are part of the update trust boundary.
Semantic code dependencies, large-graph rendering improvements and managed
sidecar restart are planned for later work.
