## Aqvenor v0.2.0-alpha

**Still an alpha.** This is the first release published under the name **Aqvenor** — the same
application previously released as Kontur Code. The rename is the headline; the substance is a
settings overhaul, an honest offline mode, and your canvas selection speaking to the model.

### What to do

- **If you were on `0.1.1-alpha`: take this one.** There is no migration to perform — the
  database, the settings and the DPAPI-encrypted keys all stay where they were in your own user
  profile.
- **If you have not installed it yet:** the [full description is here](https://github.com/rwarx/aqvenor#readme),
  and the one that matters is in *What you need* below.

### What you need

- Windows 10 version 1809 or later, or Windows 11
- The [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download) — the sidecar process the
  app starts is framework-dependent
- An API key from a provider configured in Settings — the app installs and runs without one; it
  simply cannot talk to a model

### Renamed to Aqvenor

Kontur Code is now **Aqvenor**. The product, the installer (`Aqvenor Setup`), the window and
taskbar icons, the mark in the title bar, the rotating start-screen taglines and the repository
(`rwarx/aqvenor`) all carry the new name. This release also carries fresh screenshots and the
EN/RU documentation updates that went with the rename.

### Settings that tell the truth

The settings surface had knobs the backend disagreed with, and it is expensive to believe a
guard rail that is not there:

- **The toggles for command execution, network fetch and out-of-project files no longer pretend
  to work.** The sidecar has always refused those names over HTTP, but the UI still showed
  editable switches. They now render locked with live values, the HTTP `PUT` response reports
  refused names explicitly, and the WPF host — the only writer — gained the missing
  network/external switches and their budgets.
- **Every setting is clamped where it is saved.** `SettingsLimits` bounds all six sections in
  `SettingsService`, so the WPF screen, the HTTP surface and a hand-edited row agree. A `PUT` of
  `{"maxSteps": 500}` now sticks at 100. The limits are pinned by 22 test cases.
- **Dead knobs were removed or wired.** A request-timeout control nothing read is gone;
  catalogue and connection-test calls honour the configured timeout instead of hanging into the
  600-second stream budget; the workspace index cap, the unknown-window history cap and the
  graph-context depth/share are read live rather than sitting in the database.
- **Settings are searchable and categorized** — 13 sections with a filter, a tools registry
  table, a data/diagnostics area (real app and sidecar versions, data locations, a secret-free
  config snapshot, per-section reset), Top P and nullable sampling, a System theme, and session
  behaviours (delete confirmation, auto-titles) that actually apply.

### An honest offline mode

The scripted demo theatre answered questions it had no right to answer:

- **With a sidecar running, every text goes to your real model** — including "run a demo". The
  scenarios, the canned-reply fallback, the simulated voice dictation and the dead prototype
  keys exist only where no backend exists.
- **An unreachable sidecar is no longer silent theatre.** Reachability is mirrored into the
  app state and the chat shows an offline banner with a retry button.
- The marketplace rail is renamed **Models** — it opens the model catalogue — and
  regenerating an answer routes through the retried chat's own engine mode.

### Canvas selection travels into the prompt

Selecting nodes on the spatial canvas now tags the next chat or agent run: the selection
(capped) is sent with the request, and the context builder appends the shared graph block as a
context turn. You no longer have to describe what you are looking at — show it, then ask.
Unknown focus ids produce no block rather than an unasked summary, and the planning workflow is
unchanged.

### Dock tiling, drafts and parity

- A plain sidebar click now **tiles the surface beside the current one** instead of stacking it
  behind a missing tab strip, and a restore heals pre-existing stacks. Nothing ever hides
  behind a missing tab.
- The WPF host gained **per-conversation drafts** (with tests) and **Alt-drag** from the canvas
  into the composer — files pin, notes append — matching the Electron host's drag in both
  directions.
- The file tree and the diff view are hardened against contentless rehydrated entries; the
  regression has a test.

### The installer now asks before it installs

The assisted installer gained three pages before anything is copied: a
**language choice** (11 languages — the same set as the README), a **policy
page**, and a **directory choice** so the app does not drop itself into a
folder you did not pick. The policy page states what the program can do — it
writes files and runs programs on your machine — and what it does not do: no
telemetry, no analytics, no crash reporting, no account, no project server,
everything local. The MIT licence is shown in its original English; the usage
policy and disclosures are translated for every language the installer offers,
with English as the fallback. The install is still per-user — no administrator
rights required.

The installer also **refuses to run short of disk space, in your language**,
instead of half-installing. It unpacks its payload into the drive that hosts
`TEMP`, and when that drive runs low the old setup could stop mid-copy with no
error — leaving GPU libraries and the sidecar missing, which at launch looks
like a grey empty window. The setup now measures free space up front (about
800 MB where `TEMP` lives, about 600 MB on the install drive) and refuses with
a localized message before anything is unpacked; unusual `TEMP` locations are
left alone rather than guessed at. If you already installed and the window
opens grey or empty, free space on your `TEMP` drive and run the same installer
again — it fills in what it skipped.

### Before you trust it with anything

**This program can write files and run programs.** The agent works inside one folder you
nominate and asks before every change, but that is a description of the intended behaviour, not
a guarantee. Read [`SECURITY.md`](https://github.com/rwarx/aqvenor/blob/main/SECURITY.md).

- **Open a folder you are willing to let an agent edit**, and commit your work first. Agent
  writes go straight into your working tree with nothing staged and nothing backed up.
- **Leave command execution and out-of-project file access off** unless a task needs them.

### Your data

There is **no telemetry, no analytics, no crash reporting and no account**, and no server run by
this project that your data reaches. Your conversations are a SQLite file in your own user
profile; your API keys are DPAPI-encrypted and scoped to your Windows account. Everything — the
sidecar, the storage, the graph — runs on this one machine. What leaves it is what you send to a
model provider, and only when you press Send — under *that provider's* policy. See
[`PRIVACY.md`](https://github.com/rwarx/aqvenor/blob/main/PRIVACY.md).

### Reporting problems

Security vulnerabilities go through **private reporting**, not a public issue — see
[`SECURITY.md`](https://github.com/rwarx/aqvenor/blob/main/SECURITY.md). Everything else:
[issues](https://github.com/rwarx/aqvenor/issues) and
[discussions](https://github.com/rwarx/aqvenor/discussions).
