# Aqvenor — release verification — 8 November 2026

Scope: shared server-backed graph persistence, workspace save boundaries,
GitHub Releases updates and the Windows Electron release `0.3.2-alpha`.
Earlier editor, workspace and connectivity fixes are included in this release.

## Source verification

- .NET 10 solution build with warnings as errors: 0 warnings, 0 errors.
- Full .NET suite: 1058 passed, 8 skipped, 1066 total. The skipped cases make
  live requests to paid/external providers and require configured test keys.
- Electron/renderer: 176 passed across 27 test files.
- Renderer and Electron shell TypeScript checks passed.
- Release asset collector: 7 passed. It rejects corrupt installers, inconsistent
  metadata, path escapes and replacement of already collected assets.
- Production renderer build passed. Existing large-chunk and mixed
  dynamic/static `scenario.ts` import warnings remain.
- Final self-contained Windows x64 sidecar smoke passed: embedded runtime,
  authentication, full documents, checkpoint restore, stale hash rejection and
  isolation between two workspaces.

Tests cover canonical graph rejection, undo/redo versions, field-level rebasing,
stable mutation request IDs, edits arriving during save, saved empty graphs,
legacy import, external portable changes, recovery copies and close/reopen.
Workspace transitions freeze local edits while flushing, opening or restoring;
failed server cancellation must be confirmed on retry before transition.

The server cancellation response now waits for run completion. A still-stopping
run returns 409 after 15 seconds and remains available for retry. Updater close
checks preparation, active runs, final refresh, unresolved cancellation and
workspace transitions before and after saving. Installer launch failure restores
the retry state; ordinary exit does not automatically install an update.

## Isolated packaged verification

Fixture root: `.tools/qa-release-0.3.2`. Chromium/Electron `--user-data-dir`
was verified to resolve both `userData` and `sessionData` to the fixture's
`electron-profile`; sidecar uses an isolated `AICLIENT_DataRoot`.

The Windows x64 NSIS installer and blockmap were built successfully. The local
collector rehearsal verified installer size/SHA512, every SHA256 entry and full
blockmap coverage; it also produced byte-identical `alpha.yml` and `latest.yml`.
Rehearsal source identity is the earlier baseline, not a published release SHA.

Windows screen capture failed twice with `window capture timed out`. Live
verification continued through Playwright attached to the actual packaged
Electron executable. `app.isPackaged`, version `0.3.2-alpha`, both profile paths
and the sidecar data paths were verified. The native folder picker response was
substituted with fixture paths in Electron's main process; the real renderer
buttons, preload IPC, workspace APIs and graph coordinator were exercised.

Verified in the live application:

- Code onboarding and opening workspace A imported its legacy v1 canvas: three
  nodes, note contents and one labelled edge; server exported portable v2.
- Shift selection and one drag moved two nodes, with both coordinates saved by
  the server. Undo restored both positions; Redo restored the drag.
- Node note and connection label edits were saved to the canonical graph and
  portable export. Zoom changes were also saved.
- Opening workspace B from Settings kept its intentionally saved empty graph.
  Returning to A preserved the moved nodes, edited note, edge and zoom.
- Normal window close ran the renderer save handshake and exited both Electron
  and its sidecar.
- Updates settings reported installed version `0.3.2-alpha` and channel Alpha.
  Before publication, the older GitHub release lacked channel metadata, so the
  app displayed a retryable feed error.

This live run exposed an initial CanvasView auto-fit overwriting a saved
viewport. The fix preserves server viewports during mount and hydration,
defers explicit reindex fits until ready and associates them with the workspace.
Eight mounted CanvasView cases pass, including saved, loading, switching and
offline graphs. Final packaged close/reopen verification follows below.

The rebuilt package reopened workspace A with the exact saved viewport
`zoom=0.6336, panX=-7.12, panY=209.446`. Both moved nodes, the edited note and
connection label were restored. Opening Canvas Project preserved that viewport;
normal close again exited the app and sidecar through the save handshake.

## Limits

Windows installers are unsigned. `0.3.1-alpha` and earlier require manual
installation of this release because those builds have no updater. Future
updates use GitHub metadata and installer SHA512 verification. Checks and
downloads send no workspace, chat or provider-key contents.

See `SECURITY-RELEASE-2026-11-08.md` for the scoped security review. Large-graph
rendering, semantic code dependencies, broader MCP integration and managed
sidecar restart remain outside this release.
