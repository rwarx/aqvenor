## 0. Главное: клик больше не стыкует панели

**Было.** Любой клик по пункту сайдбара добавлял панель в новый док-столбец справа
(`position: { referencePanel, direction: "right" }` в `DockWorkspace.addSurface`).
Восемь пунктов — восемь колонок; панель настроек сжималась до 150 px, кнопка
«Install» — до 2 px. Полоса вкладок была **принудительно скрыта** (`display: none`),
из-за чего альтернативы стыковке не было вообще.

**Стало.** Клик открывает поверхность **поверх панели в той же группе** — полосы вкладок нет,
переключатель — сайдбар. Стыковка стала явным действием пользователя:

| Действие | Что происходит |
|---|---|
| клик по пункту сайдбара / палитра / `Ctrl+G`, `Ctrl+,` | панель ложится поверх текущей |
| кнопка ⧉ на строке сайдбара (появляется при наведении) | колонка справа (панель вынимается из стопки) |
| `Alt+click` по пункту, меню строки → «Открыть рядом» | то же самое |
| перетаскивание пункта сайдбара к краю дока | колонка с соответствующей стороны |
| × в углу панели (появляется при наведении) | закрыть панель |

Файлы: `electron/renderer/src/components/aqvenor/shell/DockWorkspace.tsx` (без полосы вкладок,
панели внутри группы, закрытие по hover-кнопке, `splitFits`-гард),
`electron/renderer/src/styles/dockview-aqvenor.css`, `shell/Sidebar.tsx` (кнопка стыковки).

Старые сохранённые раскладки (эпоха тайлинга) больше не восстанавливаются: layout
пишется в конверте `{ v: 2, layout }`, а `v: 1`/без версии один раз отбрасывается и
пересобирается в одну группу вкладок. Иначе у существующей установки при первом
запуске снова была бы стена колонок.

Заодно исправлено поведение закреплённых чатов (`chat:<id>`): активация такой
панели больше не перекидывает фокус на главный чат.

## AQV-001 — a11y-дерево переполнялось узлами канваса · P2 · **исправлено**

- Карточки узлов больше не элементы дерева: `aria-hidden` на карточке, без
  `role="button"`; служебные кнопки внутри (соединение, заметка, перетаскивание)
  получили `tabIndex={-1}` — правило «focusable inside aria-hidden» не нарушается.
- Сам канвас (`role="application"`) отдаёт **одну** сводку:
  «Канвас — карта графа, узлов: 12, связей: 13. Те же узлы перечислены в разделах
  «Файлы» и «Граф», где до них можно дойти с клавиатуры» (`canvas.a11y.summary`,
  en/ru/de).
- Файлы: `canvas/CanvasNodeCard.tsx`, `canvas/CanvasView.tsx`, словари i18n.

Проверено в живом DOM (Vite + Chromium): 12 карточек из 12 с `aria-hidden="true"`,
0 фокусируемых потомков внутри, сводка в `aria-label`. Полноценный прогон
скринридером/UIA на 127 узлах не повторялся — нужен реальный граф проекта.

## AQV-002 — док-панели без минимальной ширины · P2 · **исправлено**

- Каждая панель создаётся с `minimumWidth: 260`, `minimumHeight: 200`
  (контекстная панель — 220). dockview выводит ограничения группы из активной
  панели, поэтому «2 px» больше не получается.
- Плюс защита от бессмысленной стыковки: если после деления на группу остаётся
  меньше `PANEL_MIN_*`, панель открывается поверх текущей и показывается тост
  «Не хватает места для стыковки» (`dock.noRoom.*`).
- Файлы: `lib/aqvenor/dock-layout.ts` (константы, `splitFits`, `readSavedLayout`),
  `DockWorkspace.tsx`.

Проверено: при ширине дока 872 px третий столбец создаётся (290/290/292 px),
четвёртый — уже нет: `Git` лёг поверх текущей панели, число групп осталось 3.

## AQV-003 — новые чаты рождались «переименованными» · P2 · **исправлено**

- В `conversations.create` уходит только реально заданный человеком титул
  (`serverCreateTitle()`): плейсхолдер «New chat»/«Новый чат»/«Neuer Chat»,
  пустая строка и титул, выведенный из первого сообщения, — не уходят. Тогда
  сервер оставляет `IsTitleUserDefined = false` и авто-тайтл работает.
- Локальная сторона уже умела игнорировать «отравленные» плейсхолдеры
  (`isPlaceholderTitle` в `store.ts`, сверка в `sync.ts`) — эта логика сохранена
  и теперь покрыта тестом.
- Файлы: `lib/aqvenor/session-titles.ts`, `lib/aqvenor/sync.ts`.

Проверено юнит-тестами (4 кейса). Серверная эвристика (`CreateAsync` в
`ConversationService.cs`) **не менялась**: в этом окружении нет .NET SDK, собрать
и прогнать 997 серверных тестов было нечем. Клиентский фикс закрывает дефект:
сервер больше не получает плейсхолдер.

## AQV-005 — пикер модели мог открыться вне вьюпорта · P3 · **исправлено**

- Оба попапа композера (пикер модели и меню метода) рендерятся порталом в
  `document.body` с `position: fixed`, позиция считается из
  `getBoundingClientRect()` якоря и зажимается в вьюпорт: правый край по пилюле,
  открытие вверх, флип вниз при нехватке места, `maxHeight` по фактическому месту,
  пересчёт на `resize` и на любой `scroll` (capture — скролл внутри панели дока).
- Файлы: `hooks/use-anchored-popup.ts` (`computePopupPlacement` — чистая функция),
  `chat/Composer.tsx`.

Проверено в Chromium (872×927): пикер модели — `x=8, y=138, 420×436`, полностью
внутри вьюпорта, якорь-пилюля на `y=614`. Тест на прежнюю регрессию
(`y ≈ −18858`) гоняет позиции якоря от −20000 до 2000 — попап всегда внутри окна.
