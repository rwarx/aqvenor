## AQV-001 — A11y-дерево переполняется узлами канваса

- **Статус:** ✅ исправлено 2026-10-26 — см. `FIXES.md`
- **Приоритет:** P2
- **Раздел:** Canvas / доступность
- **Предусловия:** Открыта панель Canvas на графе с ~127 узлами.
- **Шаги воспроизведения:**
  1. Открыть проект с большим графом (`telegram ai-agent`, 127 узлов).
  2. Открыть панель Canvas.
  3. Прочитать accessibility-дерево окна (скринридер / UIA-клиент).
- **Ожидание:** Навигация сайдбара и прочие контролы остаются в дереве; узлы канваса представлены компактно.
- **Факт:** Дерево обрезается на 400 элементах, почти целиком занятых карточками узлов канваса; сайдбар, кнопки панелей и другие контролы исчезают из дерева. Скринридер и AX-автоматизация теряют весь остальной UI. Дополнительно: клики по элементам канваса через a11y (AXPress) не запускают pointer-логику (drag/select) — интерактив канваса недоступен вспомогательным технологиям.
- **Частота:** Воспроизводится всегда при открытом канвасе с большим графом.
- **Доказательство:** Лог элементов в истории аудита (список из 400 `button «<имя файла>»`); AQV-UI-004-node-working.png (127 карточек).
- **Причина (подтверждена):** `CanvasView` рендерит все узлы как доступные `role="button"` без виртуализации; ни один из узлов не помечен декоративным.
- **Рекомендация:** Помечать карточки узлов `aria-hidden` (канвас — визуальная проекция, дублируется Files/Graph), либо виртуализировать видимые узлы и оставить суммарную a11y-подпись канваса («127 nodes, 126 connections» уже есть в статус-баре).

## AQV-002 — Док-панели без минимальной ширины

- **Статус:** ✅ исправлено 2026-10-26 (+ поведение дока изменено: клик открывает вкладку) — см. `FIXES.md`
- **Приоритет:** P2
- **Раздел:** DockWorkspace
- **Предусловия:** Несколько панелей открыты в доке.
- **Шаги воспроизведения:**
  1. Открыть последовательно Graph, Code, Git, Trajectory, Models, Workflows, Settings (каждый открывается новой панелью).
  2. Осмотреть ширину панелей.
- **Ожидание:** У каждой панели есть минимальная читаемая ширина (или панели замещают друг друга/скроллятся).
- **Факт:** После обхода 8 разделов панель настроек сжалась до ~150px; кнопка «Install» внутри карточки стала шириной **2px**, `elementFromPoint` в точке кнопки вернул `null` — кликнуть невозможно. Пользователь, уменьшающий панели, получает молча нечитаемый UI.
- **Частота:** Воспроизводится всегда при интенсивном тайлинге.
- **Доказательство:** JSON-проба `{btn:{w:2,h:28}, elementAtPoint:null}` в истории аудита.
- **Причина (подтверждена):** Dock-сплиты делят пространство пропорционально без нижней границы ширины группы.
- **Рекомендация:** Задать `minSize` группам dockview (например 180–220px) либо автоматически закрывать/схлопывать панели ниже порога.

## AQV-003 — Новые чаты создаются с титулом как у переименованных вручную

- **Статус:** ✅ исправлено 2026-10-26 (клиент не отправляет плейсхолдер; серверная эвристика не тронута — нет .NET SDK) — см. `FIXES.md`
- **Приоритет:** P2
- **Раздел:** Чаты / ensureServerSession / авто-тайтлы
- **Предусловия:** Настройка авто-тайтлов включена; серверный `CreateAsync` ставит `IsTitleUserDefined = !string.IsNullOrWhiteSpace(title)`.
- **Шаги воспроизведения:**
  1. Создать новый чат (кнопка «New chat» / Ctrl+N).
  2. Отправить первое сообщение.
  3. Наблюдать титул после рана и после рестарта.
- **Ожидание:** Чат «New chat» получает авто-тайтл из первого сообщения (или серверный титул).
- **Факт:** Чат навсегда остаётся «New chat»: клиент при апгрейде плейсхолдера отправляет текущий титул «New chat» в `conversations.create`, сервер считает непустой титул ручным (`IsTitleUserDefined=true`), и все авто-тайтлы (локальные и серверные) навсегда отключаются для этого чата. В истории пользователя — десятки чатов «New chat» с `titleUserDefined=true`.
- **Частота:** Воспроизводится с каждым новым чатом.
- **Доказательство:** `store dump` в аудите: `01a17222… | New chat | tud=true` (тестовый чат после первого сообщения); массовые `tud=true` у чатов пользователя.
- **Причина (подтверждена):** `sync.ts → ensureServerSession()` вызывает `conversations.create(current?.title && current.title !== "New chat" ? current.title : "New chat", …)` — плейсхолдосное имя уходит на сервер как осмысленный титул.
- **Рекомендация:** Не отправлять титул при создании, если он равен плейсхолдеру (передавать `undefined`) — сервер оставит `IsTitleUserDefined=false`, и авто-тайтл применится; в идеале — поправить и серверную эвристику (считать «New chat»/«New Chat» не-пользовательским титулом).

## AQV-005 — Пикер модели композера может открыться вне видимой области

- **Статус:** ✅ исправлено 2026-10-26 (портал + `position: fixed` с зажимом во вьюпорт) — см. `FIXES.md`
- **Приоритет:** P3
- **Раздел:** Composer / ModelPicker
- **Предусловия:** Окно со скроллом истории/страницей настроек в другом панели докa (позиционирование попапа относительно прокрученного контейнера).
- **Шаги воспроизведения:**
  1. В окне с несколькими док-панелями открыть пикер модели из композера (пилюля «Select a model»).
  2. Проверить позицию попапа.
- **Ожидание:** Попап раскрывается над/под пилюлей внутри вьюпорта.
- **Факт:** В одном прогоне автоматизации попап отрендерился с координатой y ≈ −18858 (полностью вне вьюпорта). Визуально повторить не удалось (проверено только программно); возможна причина — позиционирование в прокрученном контейнере док-панели.
- **Частота:** 1 из 2 попыток автоматизации; ручного подтверждения нет.
- **Доказательство:** JSON-проба `picker search: 798,-18858` в истории аудита.
- **Причина (вероятная, не доказана):** Абсолютное позиционирование попапа внутри прокручиваемого предка вместо фиксированного/портального.
- **Рекомендация:** Проверить вручную; при подтверждении — рендерить попап через портал в `position: fixed` относительно кнопки.

## Не-дефекты (зафиксировано для полноты)

- **NVIDIA HTTP 451** на запрос генерации — гео-блок провайдера, не ошибка приложения; показан честно, Retry работает. После повтора запрос на той же модели успешно вернул ответ «2».
- **OpenRouter «Access denied by security policy»** на `/image` — на текущем ключе нет доступа к image-модели (или отключён биллинг); приложение сообщило об этом человекочитаемо. Функциональность `/image` при наличии доступа working as designed.
- **Сетевые 400/404 в консоли** (3 шт. за аудит) — отсутствие опциональных файлов (например `.aqvenor/canvas.json` до первой записи); обработаны, UI не задеты.
